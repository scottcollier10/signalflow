# Database Schema Alignment - Fix Summary

## Status: ✅ COMPLETE

Fixed: January 10, 2026

## Problem

The normalizer was using n8n execution IDs (text like "4349") directly as database UUID fields, causing:
```
ERROR: invalid input syntax for type uuid: "4349"
```

## Root Cause

**Database Schema (correct):**
- `executions.id` = UUID (auto-generated by database)
- `executions.n8n_execution_id` = TEXT (n8n's execution ID)
- `executions.workflow_id` = UUID (references workflows table)

**Original Code (incorrect):**
- Tried to use n8n execution ID directly as UUID
- No separation between n8n IDs and database UUIDs
- Missing raw_json storage
- Missing workflow lookup/creation logic

## Changes Made

### 1. Models (`backend/src/normalizer/models.py`)

**ExecutionEvent:**
```python

# After:

```

**NormalizedExecution:**
```python

### 2. Parser (`backend/src/normalizer/parser.py`)

**Key Changes:**

```

### 3. Storage (`backend/src/normalizer/storage.py`)

**Major Changes:**

a) **Workflow Lookup/Creation:**
```python
async def _get_or_create_workflow(self, normalized: NormalizedExecution) -> str:
    """Get workflow UUID by n8n_workflow_id, or create new workflow."""

    # Try to find existing workflow
    response = self.supabase.table("workflows")\
        .select("id")\
        .eq("n8n_workflow_id", normalized.n8n_workflow_id)\
        .execute()

    if response.data:
        return response.data[0]["id"]

    # Create new workflow if not found
    workflow_data = {
        "name": workflow_data.get("name", f"Workflow {normalized.n8n_workflow_id}"),
        "n8n_workflow_id": normalized.n8n_workflow_id,
        "raw_json": workflow_data,
        "node_count": len(workflow_data.get("nodes", [])),
        "edge_count": len(workflow_data.get("connections", {}))
    }
    ...
```

b) **Execution Storage:**
```python
# Before:
exec_data = {
    "id": normalized.execution_id,              # WRONG: n8n ID as UUID
    "workflow_id": normalized.workflow_id,      # WRONG: not a UUID
    ...
}

# After:
exec_data = {
    # NO "id" field - let database generate it

    "n8n_execution_id": normalized.n8n_execution_id,  # n8n ID as TEXT
    "trigger_mode": normalized.trigger_mode,    # NEW
    "raw_json": normalized.raw_json,            # NEW
    ...
}

# Get generated UUID back
execution_uuid = exec_response.data[0]["id"]
return execution_uuid  # Return UUID instead of boolean
```

c) **Event Storage:**
```python

event_data = {
    "execution_id": execution_uuid,  # UUID from executions table
    ...
}
```

## Key Learnings

1. **Separation of Concerns:**
   - n8n IDs (text) ≠ Database IDs (UUIDs)
   - Always maintain both for traceability

2. **Database-Generated IDs:**
   - Let PostgreSQL generate UUIDs
   - Don't try to create them in application code
   - Get generated ID from INSERT response

3. **Foreign Key Management:**
   - Workflow must exist before execution
   - Use lookup-or-create pattern
   - Store raw JSON for debugging

4. **Schema First:**
   - Start with database schema as source of truth
   - Align application models to match
   - Don't try to force incompatible types
